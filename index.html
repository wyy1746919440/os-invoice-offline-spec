线下开票补录 · 需求说明

范围：OS 端 PC 后台「结算中心 / 开票管理」· 涉及 2 个页面（列表改造 + 补录页新建）+ 1 张详情页

一、背景与目标

1.1 当前系统逻辑

供应链订单的开票状态不是下单时就有的，而是由线上的开票单驱动：客户在供应链小程序申请开票、或财务在开票管理里新增开票，系统生成一张开票单并把订单置为「待开票 / 待审核」；财务确认开票后订单变为「已开票」，开票单作废后订单变为「已作废」。财务在「新增开票」里选订单时，系统只列出开票状态为「未开票、已关闭、已作废」的订单。

1.2 存在的问题

线下已经开过票的订单，因为系统里没有对应的开票单，会一直停在「未开票」，并长期出现在「新增开票」的可选订单列表里，财务据此可能再开一次票。

1.3 目标

提供一条把线下已开发票补录进系统的通道：补录完成后相关订单开票状态变为「已开票」，脱离「新增开票」的可选范围；补录生成的开票单在开票管理中可查、可追溯、可作废。

本页所有规则仅对 PC 后台 生效，移动端 / 小程序不在本次范围。

二、本次改动总览

页面类型改动

三、PC/结算中心-开票管理（列表与详情）

3.1 业务新增需求

1 入口开票管理列表增加「线下开票补录」按钮，点击进入线下开票补录页。
2 开票来源列表增加「开票来源」列，取值为「线上申请」或「线下补录」；查询条件增加「开票来源」筛选，默认不限制（显示全部）。
3 详情展示详情页展示「开票来源」（申请类型为「线下补录」）；导入人、导入时间即申请人、申请时间，不重复占字段。
4 作废线下补录生成的开票单支持作废；作废后，该单关联订单的开票状态回到「已作废」。

3.2 文案

列表按钮线下开票补录
列名 / 筛选项开票来源；取值 线上申请、线下补录
详情字段开票来源、导入文件名、导入人、导入时间

3.3 验收

  • 开票管理列表能看到「线下开票补录」按钮，点击后进入补录页。
  • 线上申请产生的开票单「开票来源」显示「线上申请」，线下补录产生的显示「线下补录」。
  • 选择「开票来源 = 线下补录」筛选，列表中只剩线下补录的单据。
  • 打开一张线下补录单的详情，能看到开票来源（申请类型为线下补录）、申请人、申请时间。
  • 对一张线下补录单执行作废，作废后该单关联订单在销售订单详情中的开票状态显示「已作废」。

四、PC/结算中心-开票管理-线下开票补录（新建）

4.1 需求说明

财务在线下已经给供应链订单开过票，但线上没有任何记录，订单仍显示未开票，可能被重复开票。本页用于财务把线下已开的票补录进系统：补录完成后，本次补录的订单开票状态变为「已开票」，不再出现在开票可选订单列表里。

4.2 页面结构

① 补录信息商户（必填，单选） · 开票类型（固定「快销品采购」，不可修改） · 开票日期（必填） · 导入 Excel（含模板口径说明）。
② 订单校验校验汇总（共 N 单 / 通过 X / 不通过 Y）+ 整批拦截提示 + 逐单结果表（订单流水号 / 系统订单金额 / 表格金额 / 校验结果 + 不通过原因）。
③ 上传发票至少 1 张，支持多张；png / jpg / jpeg / pdf，单个 ≤50M。
底部操作返回 / 提交。

4.3 规则

编号规则
R1 入口财务在 PC 后台「结算中心-开票管理」列表点击「线下开票补录」进入本页。
R2 选商户进入本页后先选择商户，必填，只能选一个商户。
R3 开票类型固定为「快销品采购」，不可修改；本期只处理供应链订单。
R4 开票日期必填，财务录入这张线下发票的开票日期，格式 YYYY-MM-DD。
R5 导入 Excel 1. 上传财务现有的线下开票台账，系统从表头读取「订单流水号」和「折后商品销售金额」两列，其余列不读取；表头缺少这两列任一时，提示「表格格式不正确，请使用线下开票台账模板」。
2. 模板说明中注明「导入前请将金额列另存为数值」。金额列为公式时，未重算会读到旧值，导致金额校验误判。
R6 订单识别同一个订单流水号在表格中出现多行时，合并为一个订单，金额按行相加。
R7 订单校验对 R6 得到的每个订单，必须同时满足以下四项，否则该订单校验不通过：① 订单在系统中存在；② 订单属于 R2 所选商户；③ 订单状态为「交易完成」；④ 订单当前开票状态为「未开票、已关闭、已作废」之一（即尚未开过票）。
R8 对冲单校验若订单存在对冲单（订单流水号带 -D 后缀），则主单与全部对冲单必须在本次表格中同时出现；只出现部分时，该主单校验不通过。
R9 金额校验 1. 系统订单金额取该订单在销售订单详情页展示的「订单金额」。
2. 表格金额按行先四舍五入到分，再按订单相加；系统订单金额与表格金额均精确到分后比对。
3. 两者不一致时，该订单校验不通过。
R10 结果展示页面列出本次导入的全部订单，逐单展示订单流水号、系统订单金额、表格金额、校验结果；不通过的订单显示不通过原因（订单不存在 / 不属于所选商户 / 非交易完成 / 已开过票 / 对冲单未齐全 / 金额不一致）。
R11 提交条件只要存在任一订单校验不通过，整批不允许提交，页面提示「存在校验不通过订单，请修改表格后重新上传」，财务修改 Excel 后重新上传；不允许只提交校验通过的部分。
R12 上传发票上传发票，必填，至少 1 张，支持多张；格式 png / jpg / jpeg / pdf，单个 ≤50M。
R13 提交结果提交成功后，本次补录的订单开票状态变为「已开票」，系统生成一张与本次补录对应的开票单并记入开票管理列表（开票来源为「线下补录」）。
R14 防重复同一订单一旦补录成功，再次被上传时按 R7 第 4 项判为不通过（已开过票），不会被重复标记。

4.4 文案

页面标题线下开票补录
字段名商户、开票类型、开票日期、订单流水号、系统订单金额、表格金额、校验结果
操作按钮导入Excel、上传发票、提交
提示语 表格格式错误：表格格式不正确，请使用线下开票台账模板
存在不通过订单：存在校验不通过订单，请修改表格后重新上传
未上传发票：请上传发票
提交成功：补录成功，共 N 个订单开票状态已更新为已开票

4.5 验收

  • 财务在 PC「结算中心-开票管理」列表点击「线下开票补录」，可以进入补录页。
  • 不选商户直接提交，页面提示需要选择商户；开票类型显示「快销品采购」且不可修改。
  • 不填开票日期直接提交，页面提示需要填写开票日期。
  • 上传缺少「订单流水号」列或缺少「折后商品销售金额」列的表格，页面提示表格格式不正确。
  • 上传一张同一订单号出现 4 行的表格，页面只展示 1 个订单，表格金额为该 4 行之和。
  • 上传一张包含「已开过票」订单的表格，该订单显示不通过原因为「已开过票」，整批无法提交。
  • 上传一张表格金额与系统订单金额相差 1 分的表格，该订单显示不通过原因为「金额不一致」，整批无法提交；把表格金额改成与系统订单金额一致后重新上传，该订单校验通过。
  • 上传一张只有主单、没有其 -D 对冲单的表格，该主单显示不通过原因为「对冲单未齐全」。
  • 上传全部通过的表格、填写开票日期、不上传发票直接提交，页面提示请上传发票。
  • 上传全部通过的表格、填写开票日期、上传 1 张发票后提交，页面提示「补录成功，共 N 个订单开票状态已更新为已开票」。
  • 提交成功后，打开其中一个订单的销售订单详情，开票状态显示「已开票」。
  • 提交成功后，财务再进入「新增开票」选订单，这些订单不再出现在可选列表中。
  • 提交成功后，在开票管理列表按「开票来源 = 线下补录」筛选，能查到本次生成的开票单，详情中能看到导入文件名、导入人、导入时间。
  • 把已补录成功的订单重新导一次，页面显示该订单「已开过票」，无法提交。

五、开票详情（线下补录单）

详情页交互对齐供应链订单线上开票的详情，前端结构不做大改动，仅在线下补录单上补充来源信息与作废能力：

状态横幅置顶横幅（样式同线上开票详情，可 ✕ 收起）：展示单据状态、开票来源标签「线下补录」；作废后横幅转为已作废样式。
申请信息沿用现有字段结构：票据ID、商户ID、商户名称、申请类型（线下补录）、申请人、申请时间、备注；不展示处理人 / 处理时间 / 所属时间 / 时间类型。导入人、导入时间与申请人、申请时间同源，不重复展示。
发票信息开票类型（快销品采购）、开票主体、开票日期、发票金额；上传发票影像展示（可查看原图）。抬头等开票资料以线下发票为准，系统不回填。
订单信息逐单展示订单号、订单金额、开票状态、备注，底部总计行；开票状态随本单联动（本单有效 → 已开票；本单作废 → 已作废）。
底部操作导出明细 / 作废（右下角）。作废需二次确认，确认后提示关联订单将回写「已作废」并可重新被选择开票。
