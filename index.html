线下开票补录 · 需求说明

范围：OS 端 PC 后台「结算中心 / 开票管理」· 涉及 2 个页面（列表改造 + 补录页新建）+ 1 个详情页，并联动销售订单与线上开票
本版核心变更（2026-11-04）：开票口径由「整单开票」改为 「按商品品项开票 + 订单金额累计」。 订单新增「已开票金额」与商品级已开票标记，开票状态新增 「部分开票」；台账导入从 2 列扩到 5 列，校验从订单级下沉到商品行级。

一、背景与目标

1.1 当前逻辑

  • 开票状态由开票单驱动：客户在小程序申请开票、或财务在开票管理新增开票，生成开票单并把订单置为「待开票 / 待审核」；财务确认后订单变「已开票」，开票单作废后订单变「已作废」。
  • 财务在「新增开票」里选订单时，系统只列出开票状态为「未开票、已关闭、已作废」的订单。
  • 开票单与订单的关联只到订单维度，不记录本次开票包含哪些商品；详情页的商品列表是打开时按订单实时查询的全部商品，不是开票内容。
  • 订单开票状态是单值，没有「部分开票」，也没有「已开票金额」累计字段。
  • 开票单的「申请类型」目前只有「平台开票」「客户开票」两种取值。
  • 线下已开过票的订单没有对应开票单，订单开票状态不会变化，仍会出现在「新增开票」的可选订单列表中。

1.2 问题

线下存在「为了凑客户要求的金额，一张订单只挑几个商品开票」的实际情况。按整单开票建模时，这类订单要么被迫整单标记已开票（金额对不上），要么无法补录（订单一直停在未开票、被重复开票）。

1.3 目标

把开票口径改为「按商品品项开票 + 订单金额累计」：订单记录已开票金额与已开票商品，剩余部分可后续再开；补录完成后按累计金额重算订单开票状态（已开票 / 部分开票 / 未开票），既避免重复开票，也支持一张订单分多次开。

本页所有规则仅对 PC 后台 生效，移动端 / 小程序不在本次范围。

二、本次改动总览

三、PC/结算中心-开票管理（列表与详情）

3.1 需求

R1 入口开票管理列表新增「线下开票补录」按钮，点击进入线下开票补录页。
R2 申请类型「申请类型」新增取值「线下补录」，与原有「客户开票」「平台开票」并列；查询条件「申请类型」支持筛选「线下补录」，默认不限制（显示全部）；不新增「开票来源」列。
R3 详情详情页展示「申请类型」，线下补录单显示「线下补录」；申请人、申请时间沿用现有字段，分别取本次补录的操作人与提交时间。线下补录单详情增加「本次开票商品」列表，展示商品名称、规格、数量、金额。
R4 作废线下补录生成的开票单支持作废。作废后：按该开票单记录的商品清单撤销对应商品的已开票标记 → 从订单已开票金额中冲回本单金额 → 按冲回后的已开票金额重算订单状态（归零回「未开票」、仍有余额为「部分开票」）。

3.2 文案

列表按钮线下开票补录
列名 / 筛选项申请类型：客户开票、平台开票、线下补录；单据状态新增 部分开票
详情字段申请类型（线下补录）、申请人、申请时间、本次开票商品

3.3 验收

  • 列表能看到「线下开票补录」按钮，点击进入补录页（R1）。
  • 线下补录生成的单据「申请类型」显示「线下补录」，原有单据显示「客户开票」或「平台开票」；按「申请类型 = 线下补录」筛选后只剩补录单据（R2）。
  • 提交成功后打开线下补录单详情，能看到本次开票商品清单（商品名称、规格、数量、金额）（R3）。
  • 对一张补录单执行作废：该单商品的已开票标记撤销、订单已开票金额冲回，状态按冲回后金额重算，这些商品可再次补录（R4）。

四、PC/结算中心-开票管理-线下开票补录（新建）

4.1 页面结构

① 补录信息商户（必填，单选） · 开票类型（固定「快销品采购」，不可修改） · 开票主体（随开票类型默认带出「深圳市大黄鹅商务服务有限公司」，只读） · 开票日期（必填） · 导入 Excel（五列口径 + 模板说明）。
② 校验结果汇总条（共 N 单 / 通过 X / 不通过 Y / 来源文件）+ 整批拦截横幅 + 校验明细表（列头：订单流水号 / 商品名称 / 商品规格 / 订单数量 / 系统订单金额 / 已开票金额 / 剩余可开金额 / 表格金额 / 校验结果）：订单流水号纵向合并占该订单的全部商品行，订单级结果（通过 / 不通过 + 原因 + 订单合计：表格金额、剩余可开金额）展示在合并单元格内；四个金额列逐商品行展示（系统订单金额 / 已开票金额 / 剩余可开金额取该商品在系统中的数据，表格金额取台账该行折后金额），校验结果列逐行展示行校验结果。
③ 上传发票至少 1 张，支持多张；png / jpg / jpeg / pdf，单个 ≤50M。
底部操作返回 / 提交。

4.2 规则

编号规则
R5 选商户进入本页后先选择商户，必填，只能选一个商户。
R6 开票类型 / 主体「开票类型」固定为「快销品采购」，不可修改，本期只处理供应链订单；「开票主体」随开票类型默认带出「深圳市大黄鹅商务服务有限公司」，只读不可修改、不可清空。原型已实现
R7 开票日期必填，录入这张线下发票的开票日期，格式 YYYY-MM-DD。
R8 导入 Excel 1. 从表头读取 订单流水号、商品名称、商品规格、订单数量、折后商品销售金额 五列，其余列不读取；表头缺少任一列时提示「表格格式不正确，请使用线下开票台账模板」。
2. 模板说明中注明「导入前请将金额列另存为数值」——金额列为公式时未重算会读到旧值，导致金额校验误判。
R9 商品行匹配以「订单流水号 + 商品名称 + 商品规格」与订单中的商品行做精确匹配（不做包含匹配，例如「冰红茶」不能匹配到「康师傅低糖高纤冰红茶」）。匹配不上的行判为不通过，原因「商品在订单中不存在」。
R10 订单汇总匹配成功的商品行按订单流水号合并为一个订单；表格金额 = 该订单下所有匹配成功行的「折后商品销售金额」之和。
R11 订单校验对每个订单校验四项，任一不满足即不通过：① 订单在系统中存在；② 属于所选商户；③ 状态为「交易完成」；④ 当前开票状态为「未开票、已关闭、已作废、部分开票」之一。
R12 商品防重某商品行对应的订单商品在历史开票中已开过票，该行不通过，原因「该商品已开过票」。
R13 数量校验「订单数量」与该商品在订单中的下单数量不一致时不通过，原因「本期不支持按数量部分开票，请整行开票」。
R14 对冲单校验订单存在对冲单（流水号带 -D 后缀）时，主单与全部对冲单必须同时出现在本次表格中；只出现部分时该主单不通过。
R15 金额校验剩余可开金额 = 订单金额 − 已开票金额。本次开票金额不得超过剩余可开金额，超出时该订单不通过并提示剩余可开金额；小于剩余可开金额时允许提交，订单进入「部分开票」。
R16 结果展示页面列出本次导入的全部商品行与汇总订单，逐单展示订单流水号、系统订单金额、已开票金额、剩余可开金额、本次开票商品、表格金额、校验结果。不通过原因取值：订单不存在 / 不属于所选商户 / 非交易完成 / 已不可开票 / 商品在订单中不存在 / 该商品已开过票 / 数量不一致 / 对冲单未齐全 / 超出剩余可开金额。
R17 提交条件只要存在任一行不通过，整批不允许提交，提示「存在校验不通过的商品行，请修改表格后重新上传」；不允许只提交通过的部分。
R18 上传发票「上传发票」必填，至少 1 张，支持多张；png / jpg / jpeg / pdf，单个 ≤50M。
R19 提交结果提交成功后：本次商品打上已开票标记 → 本单金额累加到订单已开票金额 → 已开票金额等于订单金额则状态「已开票」，小于则「部分开票」→ 生成一张与本次补录对应的开票单，记录本次开票商品清单（名称、规格、数量、金额），申请类型为「线下补录」。页面弹出「补录成功」提示，显示共 N 个订单开票状态已更新，并回显商户、开票类型、开票主体、开票日期、上传发票张数。

4.4 验收

  • 补录页不选商户直接提交，提示需要选择商户；开票类型显示「快销品采购」且不可修改；开票主体自动带出「深圳市大黄鹅商务服务有限公司」且不可修改（R5、R6）。
  • 不填开票日期直接提交，提示需要填写开票日期（R7）。
  • 上传缺少「订单流水号 / 商品名称 / 商品规格 / 订单数量 / 折后商品销售金额」任一列的表格，提示表格格式不正确（R8）。
  • 订单 A 共 4 个商品合计 34,466.00，台账只填其中 2 个（13,900.00 + 11,120.00）：展示 1 个订单、本次开票商品 2 个、表格金额 25,020.00，校验通过；提交后订单状态「部分开票」，已开票 25,020.00，剩余可开 9,446.00（R10、R15、R19）。
  • 第二次补录剩余 2 个商品（3,886.00 + 5,560.00）：提交后已开票 34,466.00，状态「已开票」，剩余可开 0（R19、R21）。
  • 第二次补录再次填写已开过票的「冰红茶」：该行显示「该商品已开过票」，整批无法提交（R12）。
  • 把「冰红茶」写成系统中不存在的商品名称：该行显示「商品在订单中不存在」（R9）。
  • 某商品行订单数量填成 300（系统下单数量 500）：该行显示「本期不支持按数量部分开票，请整行开票」（R13）。
  • 第二次补录金额 10,000.00（超出剩余 9,446.00）：该订单显示「超出剩余可开金额」，提示剩余可开 9,446.00（R15）。
  • 上传只有主单、没有其 -D 对冲单的表格，该主单显示「对冲单未齐全」（R14）。
  • 上传全部通过的表格、填写开票日期、不上传发票直接提交，提示请上传发票（R18）。

五、联动改造（销售订单 / 线上开票 / 定时同步）

R20 部分开票订单开票状态新增「部分开票」。销售订单列表的状态筛选、销售订单详情的状态标签、开票管理列表的状态筛选均需支持该取值；销售订单列表增加「已开票金额」列；销售订单详情展示「已开票金额 / 订单金额」，状态为「部分开票」时同时展示「剩余可开金额」。
R21 多次补录同一订单可分多次补录，累计已开票金额不得超过订单金额；同一商品不得重复开票（R12）。
R22 线上开票小程序申请开票与财务「新增开票」的可选订单范围，由「未开票、已关闭、已作废」扩展为包含「部分开票」；开票金额不得超过剩余可开金额；开票、驳回、作废均按已开票金额累计回写并重算订单状态。
R23 定时同步开票状态定时同步改为按已开票金额累计推导：等于订单金额为「已开票」，大于 0 且小于订单金额为「部分开票」，为 0 为「未开票」。

六、已知限制

  • 商品行匹配依赖台账的「商品名称 + 商品规格」与系统一致；台账被改写、用简称、规格缺失时会匹配不上，需财务按系统口径填写。
  • 不记录发票号，同一张发票的重复补录只能靠「商品已开过票」与「金额不超剩余」两道校验兜底。
  • 不按数量拆分，系统不维护商品行的已开票数量，只有「已开票 / 未开票」两种状态。

七、本期不做

  • 一张线下票跨多个商户补录。
  • 按发票号自动识别重复（开票单不设发票号字段）。
  • 同一商品按数量拆分开票（例如 500 件只开 300 件），本期要求整行开票。
